# SAFETY TELECOM

Электронный журнал ежедневных инструктажей по охране труда. Заменяет бумажный журнал: сотрудник находит себя в списке, расписывается на экране телефона, а руководитель видит, кто прошёл инструктаж, и может открыть архив по календарю.

> **Это демонстрационный прототип.** Он работает как обычный статический сайт, а данные хранятся только в браузере на том устройстве, где открыта страница. Для реального использования в компании нужен сервер (см. раздел «Что нужно для боевой версии»).

## Возможности

- **Подпись инструктажа.** Поиск сотрудника по фамилии или бригаде, подпись пальцем в рамке, зелёная кнопка «Подписано» и отметка в журнале.
- **Панель руководителя.** Создание инструктажа на день: вид, тема из библиотеки (10 тем для телекоммуникаций), объект, руководитель бригады. Счётчики, список по бригадам, фильтр «Не прошли», добавление сотрудников.
- **Вид инструктажа.** Ежедневный (предсменный), первичный на рабочем месте, повторный, внеплановый, целевой.
- **Календарь и архив.** Дни с инструктажем отмечены. По нажатию на день видны вид инструктажа, тема, объект, состав бригад и подписи. Состав бригад фиксируется при сохранении инструктажа, поэтому позже его нельзя изменить задним числом.
- Подпись нельзя перезаписать, удаления записей в интерфейсе нет.
- Адаптивный интерфейс для телефона, светлая и тёмная тема.

## Как опубликовать на GitHub Pages

1. Создайте репозиторий на GitHub и загрузите в него `index.html` и `README.md` (кнопка **Add file → Upload files**).
2. Откройте **Settings → Pages**.
3. В блоке **Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/ (root)`, нажмите **Save**.
4. Через минуту сайт появится по адресу `https://ВАШ-ЛОГИН.github.io/НАЗВАНИЕ-РЕПОЗИТОРИЯ/`.

Для локального просмотра достаточно открыть `index.html` в браузере.

## Режим руководителя

Кнопка **«Вход для руководителя»** запрашивает PIN. В прототипе он задан в `index.html` строкой `var ADMIN_PIN="1234";`. Смените его перед показом другим людям.

Это только демонстрационная защита: PIN виден любому, кто откроет код страницы. Настоящая авторизация возможна только на сервере.

## Важные ограничения

- **Данные только в браузере.** Каждый телефон видит свой отдельный журнал. Общего журнала для всей компании в этой версии нет.
- **Объём.** Браузер хранит около 5 МБ. Подписи занимают много места, поэтому хватит на несколько сотен записей.
- **Нет настоящей идентификации.** Сотрудник выбирает себя сам и может расписаться за коллегу.
- **Нет гарантии архива на 30 лет.** Если очистить данные сайта в браузере, журнал исчезнет. Резервных копий и защиты от подмены записей нет.
- **Юридическая сторона.** Пригодность электронного журнала и электронной подписи нужно проверить на соответствие законодательству Казахстана об охране труда до внедрения.
- **Персональные данные.** GitHub Pages общедоступен. Не размещайте в репозитории реальные списки сотрудников и подписи.

## Что нужно для боевой версии

- Собственный сервер и база данных (например PostgreSQL) в компании или в сертифицированном дата-центре.
- Личные логины сотрудников или ПИН-код, QR-код инструктажа на объекте.
- Журнал аудита изменений и защита подписанных записей от правок на уровне сервера.
- Архив на 30 лет: резервные копии минимум в двух местах, периодическая проверка читаемости.
- Отчёты в PDF и Excel для службы охраны труда и инспекции.
- Напоминания тем, кто не прошёл инструктаж, и русский и казахский языки.
